# Why these rustls hooks

Baseline: published `rustls 0.23.46`, tag `v/0.23.46`, revision `f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb` (also the crate's `.cargo_vcs_info.json`). `Cargo.lock` resolves `rustls-webpki 0.103.17`, `aws-lc-rs 1.19.0`, `aws-lc-sys 0.47.0` (bundled AWS-LC 5.12.0) and `jni 0.22.4`. These are audit points when upgrading:

1. **Require both RFC 7250 extensions.** A `CertifiedKey` represents an RPK as a one-element list containing the **SPKI**, despite the `CertificateDer` type name. Both built-in [client](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/client/handy.rs#L231-L263) and [server](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/server/handy.rs#L182-L204) RPK resolvers are needed, along with `requires_raw_public_keys()` on each peer verifier. The [client offers](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/client/hs.rs#L349-L363) only RawPublicKey for each role; [server negotiation](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/server/hs.rs#L223-L301) and [client response validation](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/client/hs.rs#L1084-L1105) reject a missing/wrong type. Merely inserting SPKI bytes in an X.509 resolver is not equivalent.
2. **Verify the signature as well as the pin.** The verifier's identity callback checks the sole SPKI's curve, encoding and pin policy. Its signature callback separately calls [`verify_tls13_signature_with_raw_key`](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/webpki/verify.rs#L211-L231), which parses it as a `RawPublicKeyEntity` and verifies the message with the first algorithm for the TLS 1.3 scheme. We advertise/accept only `ECDSA_NISTP256_SHA256`; the [AWS-LC mapping's first entry](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/crypto/aws_lc_rs/mod.rs#L193-L201) is P-256/SHA-256. No signature-verification assertion is manufactured here. `Signer::sign` takes an [unhashed message](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/crypto/signer.rs#L76-L90); the platform performs the one SHA-256 and the ECDSA signature.
3. **Do not publish a verifier's candidate identity.** Both [client](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/client/tls13.rs#L1180-L1233) and [server](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/server/tls13.rs#L1189-L1224) set `peer_certificates` **before** verifying Finished. `peerPin` also waits for [`!is_handshaking()`](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/common_state.rs#L106-L141), a full TLS 1.3 handshake, and the current session's own successful signing callback. The client may still need to transmit bytes at that point. A server with a null enrollment pin still uses mandatory client authentication on this same verification path.
4. **Disable resumption in both directions.** The [server builder](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/server/builder.rs#L110-L124) disables the stateless ticketer but normally enables a stateful cache and issues two tickets. Replace the cache with [`NoServerSessionStorage`](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/server/handy.rs#L8-L25), set tickets and early-data size to zero, and disable half-RTT data. The client uses [`Resumption::disabled()`](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/client/client_conn.rs#L512-L518) and disables early data. Only TLS 1.3 is compiled/configured; no provider or key logger is installed process-wide.
5. **Bound more than `set_buffer_limit`.** rustls documents that its [send buffer limit applies to application writes](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/conn.rs#L495-L543). [`read_tls`](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/conn.rs#L763-L804) may accept only part of a supplied buffer; process packets and drain available authenticated plaintext after each read. The wrapper independently bounds JNI copies, total pre-auth input, accumulated plaintext, pending TLS output, and the session table.
