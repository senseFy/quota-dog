# Physical Android handover — Cloudflare staging

This is a test of the Android pilot, not a release or an emulator test. Use an arm64 phone (Android 7.0 or later) with working cellular data and a Mac on a separate Internet connection. Keep the Mac awake. No Tailscale, provider account, USB network forwarding, Cloudflare account on the phone, or router change is required. If USB is used to install the APK, unplug it before pairing. Do not share the QR, comparison code, device identifiers, bearer, CF credentials, or raw network dumps as evidence.

## Operator setup

1. On the Mac use the local build [prerequisites](README.md), excluding the emulator and system image. Run `wrangler whoami` in the shell that will deploy. If that shell supplies a working `CLOUDFLARE_API_TOKEN`, use it directly; `wrangler login` starts OAuth and does not test the token. If using OAuth instead, run `wrangler login --scopes account:read user:read workers_scripts:write workers_routes:write zone:read` in a shell without a token and approve in a browser on **that Mac**. Never paste an API token or OAuth callback URL into a thread.
2. From the repository root run `bash scripts/host-sync/staging-host.sh`. It builds the test APK, starts **only** the fake Devin service on loopback, and opens the staging desktop dashboard. The Mac creates a disposable Keychain and outputs the **path**, not the contents, of `relay-bindings.json`. Keep the process running throughout the test. No real provider credentials or normal QuotaDog profile are needed. If you close it, the next run has a new host identity and needs a fresh staging deployment and pairing.
3. Use **only** `infra/host-sync-relay/wrangler.staging.jsonc`. It targets the dedicated `quota-dog-host-sync-staging` Worker/DO and `quotadog-sync-staging.saien.pro`, not the updater, its domain, or R2. Before a first deploy check Workers, Custom Domains and DNS in the configured account: both the Worker name and hostname must be unused. On repeat runs verify they still belong exclusively to this test. Stop on a conflict, billing prompt or plan change. Check with `wrangler deploy --dry-run --config infra/host-sync-relay/wrangler.staging.jsonc`. **In an interactive terminal** deploy with `wrangler deploy --strict --config infra/host-sync-relay/wrangler.staging.jsonc --secrets-file "$BINDINGS"`, setting `BINDINGS` to the private path from step 2. Never override an existing DNS record. The file contains the route and host verifier only, not the host bearer or device key.
4. Confirm deployment succeeded, the domain has a valid public TLS certificate, and `curl -sS -o /dev/null -w '%{http_code}\n' -X POST https://quotadog-sync-staging.saien.pro/v1/routes` returns **403**. Click **Enable host** and require **Staging relay connected**. Neither client accepts a relay address from a QR. No public route signup, `workers.dev` or preview URLs, Worker observability, or snapshot storage. Cloudflare still handles outer TLS, IPs, timing and traffic volume; this is not anonymity or a guarantee about Cloudflare's platform logs.
5. Install `androidApp/build/outputs/apk/hostSyncStaging/androidApp-hostSyncStaging.apk` on the test phone: download the private test APK there, or use `adb -s SERIAL install -r ...` over USB. No `adb reverse`, emulator, VPN, phone hotspot or proxy. It installs alongside regular QuotaDog; the application ID is `saien.quotadog.hostsync.staging`. Do not log in to any provider on either device. End the test by revoking the phone, closing the disposable host and retiring **only** the test Worker/domain/DO with the account owner's approval; do not touch production.

## Acceptance cases (fresh fixture)

1. With Wi-Fi on, use the camera in **QuotaDog Staging** to scan the Mac's **Pair a phone** code. Compare the numbers and approve on the Mac. The phone must show **Computer connected** and no accounts. Share only the personal Devin source, with **Allow refresh**. The phone should show 25% daily used, 75% weekly used and USD 2.50; the second source (97% daily used) must not appear. The fixture on the Mac must have `count=1`, `unshared-count=1`.
2. Hold the next provider response on the Mac (`curl -fsS -X POST http://127.0.0.1:18788/hold`). On the phone tap **Refresh on computer** once; wait for `curl -fsS http://127.0.0.1:18788/count` to return `2`. Disable Wi-Fi **and mobile data** briefly. Confirm the phone is offline and still shows 25% with the old collection time. Release the response on the Mac (`curl -fsS -X POST http://127.0.0.1:18788/release`) and wait for the desktop's personal source to show 38%. If the provider timed out, restart the case with a fresh fixture; do not count it as a handover.
3. Enable **only cellular data**. Verify the phone's active Internet connection in Android settings (no Wi-Fi, VPN, tethering or Ethernet); keep the Mac on its original network. Return to the app. **Without another QR, approval or refresh tap**, the phone must show **Computer connected** and the new 38% reading. `count` must still be `2`. Record network type, before/after values, provider counts and time to reconnect. An online indicator, cached card or screenshot alone does not pass.
4. Still on cellular, tap **Refresh on computer** once. Expect 53% daily used and `count=3`, `unshared-count=1`. Return to Wi-Fi or close and reopen the phone app: expect the same authorized 53%, no re-pairing and no fourth query. Revoke the phone on the Mac while connected; the card must disappear. No relay data dump is needed.

If a phone or a second working network is unavailable, record the physical test as **not run**. A local Worker, a dry-run deployment or an emulator is not equivalent.
